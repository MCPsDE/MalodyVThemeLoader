# Malody V BepInEx Installer

This document describes the standalone installer and the exact runtime target
for another developer or coding AI.

## What It Installs

The installer is intentionally separate from ThemeLoader. It installs only the
official BepInEx IL2CPP Windows x64 distribution and a Malody-specific config:

```text
Malody V/
  winhttp.dll
  doorstop_config.ini
  .doorstop_version
  BepInEx/
    core/
    config/BepInEx.cfg
    plugins/
    interop/       # generated by BepInEx/IL2CPP on first run
    unity-libs/    # generated or supplied for the target Unity build
  dotnet/
```

It does not install:

- ThemeLoader
- ThemeManager
- `catalog.json`
- any theme package
- `Assembly-CSharp.dll`
- generated interop assemblies
- a user plugin
- a game launch shortcut

The installer never starts Malody V automatically.

The GUI also has a default-checked option for the official
`BepInEx.ConfigurationManager` IL2CPP plugin `v19.0`. Its interface is
English; there is no official Chinese localization bundled here. Clear the
checkbox to install only BepInEx. The manager archive is embedded into the
installer and is not downloaded during game installation.
The package is the official asset named
`BepInEx.ConfigurationManager_IL2CPP_v19.0.zip`.

## Exact Target

| Item | Value |
|---|---|
| Game | Malody V Windows x64 |
| Unity | `2022.3.62f2` |
| Scripting backend | IL2CPP |
| Required game files | `Malody V.exe`, `UnityPlayer.dll`, `GameAssembly.dll`, `Malody V_Data/il2cpp_data` |
| BepInEx | `6.0.0-be.785` |
| BepInEx build | `6abdba4` archive build |
| Official archive SHA-256 | `2a7cbf74d26abe4765c3e662db1721b923bac39849ebfef2ca5dc7de7e2d9b7f` |
| Plugin target | `net6.0` |
| Installer target | .NET 8, self-contained, Windows x64 |
| Plugin template | `BepInEx.Templates 2.0.0-be.4` |
| Optional manager | Official `BepInEx.ConfigurationManager` IL2CPP `v19.0` |
| Optional manager archive SHA-256 | `3ea26a2c354a1d960beca4c61a397c72a1641cb5872f6f89e7d972e15d8cfb29` |

Do not silently change the BepInEx build. If the game or BepInEx version
changes, treat it as a new compatibility target and regenerate interop files.

The installer uses the BepInEx IL2CPP Windows x64 package. BepInEx has separate
packages for Mono and IL2CPP games, and IL2CPP games require a first run to
generate additional modding files.

## Steam Detection

The installer checks:

1. The directory containing the installer.
2. Steam registry values:
   - `HKCU\Software\Valve\Steam`
   - `HKLM\SOFTWARE\WOW6432Node\Valve\Steam`
   - `HKLM\SOFTWARE\Valve\Steam`
3. The default Steam paths:
   - `C:\Program Files (x86)\Steam`
   - `C:\Program Files\Steam`
4. Every Steam library listed in `steamapps/libraryfolders.vdf`.
5. `steamapps/common/MalodyV` and `steamapps/common/Malody V`.

The user can still select a directory manually.

## Install Safety

The installer:

- stages the embedded payload in a temporary directory;
- refuses to overwrite an unowned `winhttp.dll`;
- refuses to overwrite other unowned bootstrap files;
- preserves existing `BepInEx/config`, `BepInEx/plugins`, `BepInEx/interop`,
  and `BepInEx/unity-libs` files;
- records owned files and hashes in
  `BepInEx/MalodyV-BepInEx.install.json`;
- uses atomic temporary-file moves for copied files;
- backs up replaced owned files under
  `BepInEx/.malody-bepinex-backup`;
- supports install/repair, verify, and uninstall;
- removes only files recorded by its own manifest.

Normal BepInEx plugins are compiled DLLs placed in `BepInEx/plugins`. The
BepInEx loader discovers plugin classes through the `BepInPlugin` attribute.

## Build

Prepare the pinned BepInEx vendor payload:

```powershell
.\scripts\prepare-dependencies.ps1 `
  -GameRoot 'E:\Program Files (x86)\Steam\steamapps\common\MalodyV'
```

Build the standalone installer:

```powershell
.\scripts\build-bepinex-installer.ps1 -Version 1.0.0
```

Output:

```text
artifacts/release-bepinex/MalodyV-BepInEx-Installer-1.0.0.exe
artifacts/release-bepinex/SHA256SUMS-BepInEx-1.0.0.txt
```

The payload is embedded in the EXE. The release machine does not need to
download BepInEx during installation.

## CLI Test Commands

The GUI is the normal interface. The installer also exposes commands useful
for disposable integration tests:

```powershell
$env:MALODY_BEPINEX_PAYLOAD = 'artifacts\malody-bepinex-payload.zip'
$env:MALODY_BEPINEX_QUIET = '1'

MalodyVBepInExInstaller.exe --install 'E:\...\MalodyV'
MalodyVBepInExInstaller.exe --verify 'E:\...\MalodyV'
MalodyVBepInExInstaller.exe --uninstall 'E:\...\MalodyV'
```

The CLI installs ConfigurationManager by default. To perform a pure BepInEx
installation, set this before `--install`:

```powershell
$env:MALODY_BEPINEX_INSTALL_CONFIGURATION_MANAGER = '0'
```

Run the disposable integration test:

```powershell
.\scripts\test-bepinex-installer.ps1
```

## Plugin Development

### Generic plugin

For a simple plugin that only logs, reads configuration, or uses general
Unity/BepInEx APIs, the Malody game source is not required. Use the exact
BepInEx IL2CPP target and compile against the BepInEx interop assemblies.

The official templates can be installed with:

```powershell
dotnet new install BepInEx.Templates::2.0.0-be.4 `
  --nuget-source https://nuget.bepinex.dev/v3/index.json
```

The template to choose is:

```text
BepInEx 6 Unity Il2Cpp Plugin
```

Run Malody V once after BepInEx installation before compiling a plugin. This
allows the IL2CPP preloader to generate the interop environment.

Minimal plugin shape:

```csharp
using BepInEx;

namespace Example;

[BepInPlugin("example.malodyv", "Example Malody V Plugin", "1.0.0")]
public sealed class Plugin : BasePlugin
{
    public override void Load()
    {
        Log.LogInfo("Example plugin loaded.");
    }
}
```

Build the plugin DLL for `net6.0`, then copy it to:

```text
Malody V/BepInEx/plugins/Example/
  Example.dll
  AnyDependency.dll
```

Do not copy a second BepInEx core into the plugin directory. Do not bundle
`winhttp.dll` inside a plugin package.

### Game-specific plugin

For code that accesses Malody types, scenes, UI, Live2D, or game methods, the
source repository is helpful but not mandatory. You do need game-specific
metadata or inspection results:

- `Assembly-CSharp.dll` generated for this exact Malody build;
- Unity IL2CPP interop assemblies;
- Unity engine interop assemblies;
- type/method signatures and scene/object names;
- runtime behavior verified against this exact game version.

For this repository, generated compile-time references are under:

```text
generated/game-libs/
```

They are generated from an isolated interop host by
`scripts/prepare-dependencies.ps1`. The real source and installed game are
read-only reference inputs.

### Compatibility rules

- Target IL2CPP, not Mono.
- Target Windows x64.
- Pin `BepInEx.Unity.IL2CPP` to `6.0.0-be.785`.
- Target `net6.0`.
- Test after BepInEx has generated interop files.
- Fail closed when the game version or required type signature is different.
- Put dependent DLLs beside the plugin DLL.
- Use `BepInDependency` for plugin-to-plugin dependencies.
- Do not patch score, judgement, replay, input, purchase, ownership,
  authentication, or network logic for a visual plugin.
